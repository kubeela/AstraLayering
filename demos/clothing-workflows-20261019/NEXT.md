# 后续优化约定

本 MR 保存现有工作流及关键工程／过程图片，以下通用改造留待下一轮实施。

## clothing-part-layering 的深度判定

独立运动、变形、显隐和控制仍是判断 group／part 的核心。衣服从外到内分析，开放袖口、衣领只是身体穿插的例子，不套固定衣型先验。输入仍为简化穿衣角色，通过原生生图提取匹配原身形、姿态和坐标的纯衣服参考。

大部分 part 维持单深度；同一连续物件确实跨越其他部件前后时，可允许一个逻辑 part 对应多个深度区域。多值须提供原画布坐标系、精确像素分界折线、两侧归属、相邻件层序，以及共同逻辑父 part／运动关系，避免为了纯排序关系反复回到上游拆组。具体数据格式和兼容方式下一轮确定。

## clothing-raster-layering step01 自行拆层

主流程仍是 RGB 控制、逐件生图、遮挡补全及 Krita 配准修画。遇到同一 part 的真实穿插，绘制 agent 可以将已经生成的整件直接分成多个普通绘画层，不再仅因单层排序冲突而 block 或退回 part。

拆层方案与脚本由绘制 agent 自己判断、编写和执行；外部只负责侦查和交接。保持物件连续性及共同运动关系，通常不需要补画，确有缺口时可适当补画。保存逻辑 part 到实际图层的映射；深度分片不等于新增独立运动部件。

reviewer 每次使用新上下文，反馈原样交给固定绘制 thread。每轮问题都要处理，最多两轮 review，第二轮修复后不再 review。允许依据参考修正不准确色块的局部轮廓和归属，并记录偏差；不额外添加外层审批门槛。衣料内部结构或材质缺失不能误判成“本阶段不画的阴影”，仍不新增 AO、投影或人为阴影。

`.running`／`.completed` 与 Markdown 的恢复语义保留；step02 必须在绘制、review 和必要修复结束后才完成。

## 可选功能：图片数量触发压缩

图片数与 token 预算分别处理，未来做成显式可选项。模型、provider、鉴权和内置 image_generation 仍由外部 Codex 管理，工作流不另接生图 API。

本次上游返回单请求最多 50 张图片，token 阈值未到时也会越限；原生 compact 若仍携带全部历史图，同样可能失败。临时方案将 token 阈值设为 256000，在工具返回后、下一次请求前按图片出现次数计数，达到 40 时于同一 thread 原生压缩。仅该压缩请求使用文字投影，成功后正常请求恢复视觉；原图文件和绘画进度保留。实跑成功完成了 9 次自动压缩。

通用实现需支持不同上游阈值、计入原生生图结果及批量工具返回、处理压缩失败，并记录触发与恢复结果。不能静默永久关闭视觉或更换绘制 thread。压缩会损失旧视觉细节，agent 应能重新打开保留的图片。先核实 Codex／SDK 的可用接口，再确定实现位置；本次临时补丁不是已支持的公开配置，也未作为工作流功能提交。
