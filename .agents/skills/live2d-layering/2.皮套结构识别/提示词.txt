观察本轮角色参考图，只建立可嵌套的 `group` 树，交付 `structure/groups.json`。本步回答“哪些对象或空间结构应分别组织、它们属于谁”，不决定具体绘制单元，也不安排画法、动画或后续制作批次。

按图中实际内容分组：
- 一个 group 可以包含下级 group；层级按语义归属和可拆的空间结构建立，不限定深度，也不强制所有类别在同一层。每个 group 只在树中出现一次，兄弟节点不得同名。
- 每处可见主体最终都要落到一个叶 group。父 group 若有不属于任何现有子组的可见区域，就补一个有具体语义的子 group（例如 `face_base`），不要让父组自身兼作叶组；这保证后续能按最底层分组逐一绘制。
- 语义上完整的对象先保持完整。`face` 可以包含 `eyes`、`mouth` 等；`eyes` 可以包含 `left_eye`、`right_eye`，此时不继续拆眼白、虹膜、眼皮或高光。左右以角色自身为准。
- 头发可以在这一阶段多拆一层：依据可辨的基本几何结构，将刘海、鬓发、侧发、后发、双马尾等列为 `hair` 的下级 group；只列图中确有、边界能辨认的结构，不逐根拆发丝。
- 衣物、配饰、兽耳、角、手持物以及非人物对象，按实际语义名称和必要的前后、内外、左右空间关系组织。可用父 group 汇集相似对象，也可直接作为独立 group；不要因为将来可能摆动或需要特殊画法，就提前归入制作类别。

分组命名采用小写英文 snake_case。语义确实吻合时，沿用现有标准名，例如 `face`、`eyes`、`mouth`、`hair`、`body`、`arms`、`lower_body`、`clothing`；这些名字可以出现在树的不同层级，不要求平铺成固定清单。没有恰当标准名时，直接使用对象自身的具体语义名，例如 `hat`、`glasses`、`earrings`、`lamp`，不要用 `generic` 兜底，也不要使用 `physics_details`、`special_parts` 这类制作或动画类别充当结构分组。

输出必须是合法 JSON，不加 Markdown 围栏。顶层为 `subject`（`character` 或 `other`）和 `groups` 数组；每个 group 只有 `name`、`groups`，必要时可加简短 `note` 说明图中辨认依据或空间关系。叶节点的 `groups` 为 `[]`。group 的身份由整条父子路径确定，不另造 `id`。例如：

{
  "subject": "character",
  "groups": [
    {
      "name": "face",
      "groups": [
        {"name": "eyes", "groups": [
          {"name": "left_eye", "groups": []},
          {"name": "right_eye", "groups": []}
        ]},
        {"name": "mouth", "groups": []},
        {"name": "face_base", "groups": []}
      ]
    },
    {"name": "hair", "groups": [
      {"name": "bangs", "groups": []},
      {"name": "left_twin_tail", "groups": []},
      {"name": "right_twin_tail", "groups": []}
    ]}
  ]
}

示例只说明格式，实际节点必须依据输入图取舍。交付前检查：可见区域均归入叶组，没有把同一对象重复放在多处，没有把不同对象混成一个含糊组；标准名只在语义吻合时使用；眼部仍停在整眼层，头发基本结构没有遗漏。本步不输出 `kind`、`part`、`visibility`、`separate_for`、阴影或高光条目。
