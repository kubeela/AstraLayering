# 衣装工作流调度规则

本文件只规定通用执行与交接方式；任务顺序由编号目录决定，输入输出由各级 `流程.yaml` 声明，具体制作要求写在对应节点提示词中。

## 调用与输入

读取[根配置](流程.yaml)，将用户提供的素材绑定为绝对路径，并将用户指定的输出目录作为本轮工作根目录；仅询问声明的必需素材或输出目录中的缺项，不追加资料清单，也不自行搜索旧任务获取隐含输入。

输入文件只读，所有产物与临时文件写入工作根目录；模板目录和输出目录分开。用户仅要求规划或修改流程时，不启动制作任务。

## 读取与绑定

- 按目录编号逐级展开、按数字排序；容器仅组织子任务，不额外执行父任务。实际节点读取自己的 YAML、提示词及 `.model` 标记。
- 普通 `inputs.<名称>` 引用根输入；循环内部引用该循环已绑定的输入。`nodes.<id>.<名称>` 引用已完成节点结果；`asset` 相对所在 YAML，普通产物路径相对工作根目录。
- `if / then / else` 按声明条件选择分支；用于条件的字段缺失或类型错误时交负责生成该字段的 worker 补正，不自行猜测。仅引用已有文件的输出直接发布路径，不复制或另派任务。
- 派发资料限节点声明的本轮输入、上游产物和工具。教程知识由编写者放入实际节点提示词，不在执行时追加教程原文、其它技能或整套流程文档。

## worker 与循环

- 从语言 `.model` 文件名最右侧拆出推理强度；新 worker 用 `spawn_agent` 显式指定模型、强度及 `fork_turns: "none"`。相同 `worker` 的串行任务用 `followup_task` 续做，不同 `worker` 使用独立会话；省略时以节点 `id` 为会话身份。
- `foreach` 先绑定节点输入，再读取声明数组，以 `as` 指定的名称交接当前项及序号、总数和 `is_last`。串行循环的 `carry` 从节点初始输入开始，每项使用上一成功项的最新产物；占位符按当前项替换。
- `when: last_item` 的输出只交给末项；循环全部完成才发布循环节点的最终输出。不要把局部进度当作整阶段完成，也不要额外派发配置中不存在的组装或检查任务。

最小交接格式：

```text
工作根目录：<绝对输出目录>
提示词：<节点提示词绝对路径>
输入：<绑定名＝实际路径或当前项数据>
循环上下文：<仅循环任务：当前项、序号/总数、is_last>
输出：<本次声明的产物路径>
读取提示词并执行，命令工作目录设为工作根目录。
```

## 生图与审查

- `imagegen.model` 由总控直接调用生图工具；读取节点声明的生图提示词，只传 `imagegen.inputs` 列出的图片与自然语言要求，不把调度参数、路径或结构 JSON 混入生成要求。保存声明产物，确认可读即可。
- 仅执行节点明确声明的独立审查，并使用独立于绘制者的会话。审查报告为 `pass / revise / blocked`：只有 `pass` 发布审查通过的输出；`revise` 交原绘制者在最新产物修具体问题，再由同一 reviewer 复验问题项；`blocked` 说明实际缺项，不无限重试。
- 总控核对规定交付和必要审查状态；节点内的视觉自查由对应 worker 完成，复用现有证据，不重复截图、核哈希或追加收尾审查。

## 完成与续跑

在工作根目录的 `运行记录.md` 简记输入绑定、节点/循环进度、实际 agent ID、产物路径和审查状态。续跑按已成功交付恢复最新产物与会话；会话失效时交接当前稿及未完成范围，不用早期整图覆盖后续成果。

最终文件以节点输出声明为准；总控汇报实际完成范围和未解决项，不把静态素材交付表述为动画绑定已完成。
