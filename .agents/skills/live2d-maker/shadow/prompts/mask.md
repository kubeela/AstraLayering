# 制作能随投影部件运动的 Live2D 阴影素材

使用 Krita 的画笔、路径／选区和透明度继承直接绘制、修整阴影形状，不调用生图模型，不重生成角色素材。从现有组装 KRA 制作新的分层工程，分析 simplified 参考中**部件之间的投影阴影**。保留身体、衣服褶皱的固有明暗、线稿和高光；不重新研究或生成整套表面光照。

## 先分析关系

逐处观察 simplified：刘海／发束→脸、头／下巴→颈、袖口→手臂、裙摆→大腿、衣摆／饰品→被遮挡的表面等。根据该角色实际设计筛选，不为没有的部件硬加阴影，也不只限于以上例子。参考图的阴影轮廓决定画法；组装图的画布、轮廓、位置决定配准。读取人物和衣服的 groups.json、occlusion.json，核对实际 KRA 的前后顺序、穿戴遮罩、半透明区域，建立真实投影物／受影物关系。分析与不适用项写入 report.md。

分件重新绘制通常已经自然去掉了原来的投影。先检查现有底色，干净的直接用。只有受影区域仍带旧投影而会叠黑时，才在新工程里局部补出无投影底色；不要统一平涂、改画角色或抹掉褶皱。输入工程保持只读，保留原有部件、遮罩、精度和可编辑性。

## 补全阴影并裁切

每个独立运动的投影物对应独立阴影绘画层。把阴影补成包含充分延伸和运动余量的完整形状，面积一般远大于静帧中的实际可见投影；裙摆阴影可按整个裙摆及合理延伸绘制，不能只画露在腿上的那一条。保留受影面轮廓之外、运动后可能进入裁切范围的内容。不要将阴影像素预先裁死在接收面边缘。完整阴影依据**投影物的运动**发生形变；受影部件的实时轮廓负责裁切。后续可共用运动域或使用独立阴影 deformer 修正形状和相位，不强制为投影物的直接子节点，也不要求复制同一变换。这里制作素材和关系，不制作动作／光向关键形，不创建 Cubism 模型或冒充已绑定动画。

真实参考原则：Milly 原模型的完整裙影为乘算，运行时一张影层同时裁切到左右腿，并响应裙子与裙子 s 的独立参数；发影为普通不透明色，运行时裁切到 faceM。阴影与受影裁切来源可以独立运动。不要从图层名称猜混合模式，不把任意 mask 都认成投影。一个来源照到多个受影部件时，可以共享完整影层和联合裁切；需要不同颜色或响应才拆层，避免左右腿影重复乘算。参考的面积倍率不是新角色的强制门槛。

在 Krita 使用原生隔离图层组（关闭穿透）和阴影层的“透明度继承”（alpha inheritance），以同组内受影底色／受影轮廓的联合覆盖裁切。需要多个受影层时记录它们，不丢失当前穿戴蒙版。必要的可关闭透明度蒙版仍保持原生。阴影层 UUID、投影物与接收面 UUID 要从保存工程读取；不能仅在 JSON 声称有裁切而工程实际没有。

阴影应处于受影颜色之上、相关五官与线稿之下，保持眼口清晰。对重叠发束投影优先用采样参考阴影颜色的正常、不透明颜色层，避免两次正片叠底造成黑斑；其他互不重叠、确实适合调色的投影可使用正片叠底。不是一律禁止正片叠底，选择依据和合成检查写入报告。保留原图风格，软硬边由参考决定。

## 检查与交付

逐处对照 simplified 和组装原画；临时平移／摆动每个投影物与其完整阴影，检查受影裁切、余量、重叠区域、五官可读性，然后复位。该检查是素材运动检查，不能声称已完成 deformer 绑定。重开最终 KRA，确认裁切与显隐，导出原尺寸、透明背景、无损 PNG。关闭新增阴影组应回到原有干净底色，局部去旧影的地方在报告中标明。

交付 character-shadowed.kra、与其保存合成图一致的 character-shadowed.png、report.md，以及 shadows.json：

```json
{
  "version": 1,
  "shadows": [{
    "id": "skirt-to-thigh-left",
    "casterPartId": "clothing:<groups.json里的原ID>",
    "receiverPartId": "character:<groups.json里的原ID>",
    "casterLayerUuids": ["<最终KRA中的UUID>"],
    "receiverLayerUuids": ["<最终KRA中的UUID>"],
    "shadowLayerUuid": "<完整阴影绘画层UUID>",
    "clipBaseLayerUuid": "<同隔离组内受影裁切底层UUID>",
    "follow": "caster",
    "blendMode": "normal",
    "notes": "投影范围、运动余量、补全与颜色选择依据"
  }],
  "excluded": [{"relation": "<候选关系>", "reason": "<角色实际没有该投影或为何不适用>"}]
}
```

示例不意味着角色必须有裙子。多受影部件使用 receiverPartIds 数组替代单个 receiverPartId，receiverLayerUuids 列出全部受影来源；clipBaseLayerUuid 可指向同隔离组内联合覆盖的受影子组。follow="caster" 记录投影运动的来源语义，不宣称已经绑定同一 deformer；notes 说明预期独立修正、余量与颜色依据。正常色层 blendMode 为 normal；正片叠底为 multiply。所有 part ID 必须真实存在，所有 UUID 来自最终保存工程，不填占位符。不同运动关系不能共用一个阴影层。完全没有适用投影时，保留原工程并明确说明理由，不能空报告假装完成。
