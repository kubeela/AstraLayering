## 共用 Krita 环境与故障恢复

本 section 有一个专属的私有 Krita，通过 `krita` 工具管理和使用：status 查看状态与 pid，start 按需启动（进入 section 时不会自动启动），run 执行 Python 脚本，restart 在崩溃或卡死后重新启动。Krita 在无人值守的界面中运行，只通过 Python 操作；section 结束时由框架关闭，不要自行启动其他 Krita 进程或改动用户的 Krita 配置。

脚本使 Krita 崩溃或卡死时，用 restart 重启，再从已保存的 .kra/PNG 重新打开；未保存的修改和 session 变量会丢失，较长的工作应分段保存。工具返回 ok=false 时先读 hints 和 error，修正后再执行，不要反复提交同一失败脚本。

保持已有工程与会话。可恢复的路径、启动、脚本错误先诊断修复再接续，禁止伪造交付、跳过验收。只在必要输入、权限或工具仍真实不可用且已记录具体恢复尝试时报告执行障碍。绘画与质量判断仍按各阶段自己的提示词进行。
