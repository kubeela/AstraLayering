# 嘴部必做与角色可选目录

目录 v1，2026-10-20。编号沿用本轮与用户确认的制作清单，不重新命名或改变数量。依据：[M01 视频解析](sources/mouth-video.md)、[网格制作](04-mouth-mesh.md)与[Jianma 选择记录](cases/jianma.md)。

**这是正式的选项定义与制作判断，不是“所有选项都已实战做成”。** S04–S08、F 组的扩展子项等仍是条件目录。原型测试通过也不自动代表牙唇语义、美术和所有组合通过；本轮上唇混入牙齿的反例见[质量排查](07-review-and-quality.md)。

## 一、范围与判断原则

共用基础系统按下列七项制作；特色能力按角色原画、已有素材、目标动作和实际形变结果决定。这里的“动态判断”是逐角色制作和素材变化后的重新评估，不是运行时随意改变角色的嘴型风格。

**嘴型制作只包含素材、网格、形变、遮挡、参数、关键形和制作预览。语音识别、音量驱动、音素映射、摄像头捕捉及其校准不属于本制作清单，不计入必做或选做数量。** 嘴部余弹沿用独立的物理系统；本清单只规定形变与闭合边界，不另列物理引擎开发任务。

- 已有的角色标志必须保留。例如原画本就有虎牙，正常嘴型也必须保留其身份特征，不能因为它属于条件项而丢掉。
- 虎牙这类牙齿身份特征依据角色原有设计；原画没有、用户也没有要求新增时，不因技术上可以形变就主动加上。剑妈本轮明确不做虎牙。
- 六层嘴部是剑妈当前的素材情况，不是所有人物必须画齐六层。简化画风可以没有下牙、舌头或独立唇彩。
- 先复用原素材、调整网格、局部拆片和遮挡。只有目标动作需要的表面确实不存在，或实际拉伸破坏画风，才增加具体补画项；不能按“猫嘴／虎牙／吐舌头”的名字直接判定需要重画。
- 自动分析可以发现图层、覆盖范围和参数缺口；是否适合猫嘴、露齿或夸张表情，依据角色设定和用户要求。不能把已有一张舌头图片直接登记成已支持吐舌动作。

## 二、所有此类角色的基础必做：七项

| 项目 | 必须完成的内容 | 方法与检查点 |
| --- | --- | --- |
| 1. 素材与静止状态检查 | 识别唇线、口周皮肤、开口、现有内部／装饰层，保存原画基准与准确坐标 | 嘴角接合、透明边、内部覆盖余量、脸底是否完整；缺失部件按目标动作决定，不机械补齐所有牙舌 |
| 2. 嘴唇及口周网格 | 上下唇分别控制，嘴角、中线和左右弧段可调，外圈接回静止脸皮 | 沿唇线布置多排窄带网格，皮肤向外放疏；控制线宽、连接和网格方向，不把整张嘴统一压扁 |
| 3. 基础参数与关键形 | 项目采用开合 0–1、嘴形 -1–1 两轴；先制作悲／自然／喜 × 闭／开六个边界关键形 | 调整幅度以保留角色画风；扫描中间形态，只在微张或曲率转换不好看处增加修正关键形。六形是本项目起点，不是所有 Live2D 模型的唯一规定 |
| 4. 分层联动与遮挡 | 口腔开口由上下唇边界共同决定；现有牙齿、舌头、装饰各自响应 | 内部层保留形体与覆盖余量，靠遮挡控制露出；闭合不漏白牙、黑腔或双唇线。外露虎牙等另有可见性规则 |
| 5. 贴图与父级形变衔接 | 颜色、选区和已有法线／深度共享形变；接入现有头部父级时保持坐标一致 | 牙齿、口腔与脸皮的贴图归属分别检查；修正法线方向，避免闭嘴黑缝。没有法线／深度素材的角色不因此强制新增生图任务 |
| 6. 同页制作与保存 | 嘴型页签复用人物预览；开合／嘴形、关键姿态、网格和分层检查、连续扫动、暂停逐帧、复位与保存 | 保存角色与皮套版本对应的绑定及自定义值。辅助网格显示与完整网格编辑器是不同交付能力，不混称已实现 |
| 7. 中间过程验收 | 原画静止、极值和典型组合都能正常显示 | 优先检查微张、闭合终点、嘴形跨零、饰品越过唇线、舌头收回；不翻折、不破线、不漏边、不降低原图渲染精度 |

## 三、供后续工作流使用的明确目录 v1

以下是本项目拟采用的首版制作目录，不是 Live2D 官方标准，也不是对所有画风的穷举。编号用于需求和工作流引用；剑妈已实现 S00–S03 对应的代码键，其余轮廓仍未实现。新增轮廓需说明与已有项的结构差异并追加编号，不复用旧编号或悄悄改变其含义。

### 3.1 轮廓预设：一个基础项、八个选做项

轮廓预设描述“嘴外形是什么”。选做项表示可供角色选择，不能据此要求每个角色做齐。原画本来就是猫嘴时，S03 对该角色属于必保留特征。

| 编号／固定键 | 名称 | 明确的轮廓定义 | 优先方法与边界 |
| --- | --- | --- | --- |
| S00 `natural` | 普通嘴（基础） | 角色原画的自然唇线，通过基础开合和嘴形表达闭嘴、张嘴、微笑、下撇 | 上下唇与嘴角的六个基础关键形；微笑、难过、大笑不重复列为轮廓类型 |
| S01 `round` | 圆口／O 嘴 | 开口呈圆或椭圆，嘴角弱化；小 O 与大 O 属于同一种轮廓 | 调上下唇弧度、开口高度与宽度，不靠横向缩小整片纹理；开合为零时回到所制作的闭合唇线 |
| S02 `pout` | 嘟嘴／亲吻嘴 | 嘴唇向中间聚拢，并有前噘的唇部曲线；可以闭合或留小口 | 联动唇线曲率、中央唇峰和周围皮肤，二维形变表现前噘；不能把它实现成单纯窄嘴。侧向「3」形是该项的定向变体 |
| S03 `cat` | 猫嘴／ω 嘴 | 中央转折与左右两瓣弧线构成猫嘴轮廓 | 局部曲线与网格形变，保留厚度、嘴角接合和角色原画；与开合的联动另做关键形 |
| S04 `wave` | 波浪嘴／～ 嘴 | 嘴线有连续、圆滑的多次起伏，用于委屈或不安 | 沿唇线设置圆滑波峰和波谷；它是静态轮廓，抖动动画不包含在这个枚举中 |
| S05 `zigzag` | 折线嘴／锯齿嘴 | 嘴线有尖锐的折点，区别于 S04 的圆滑起伏 | 控制折点与线宽、避免三角形翻折；这里指唇线折角，真正的尖牙归 F01 |
| S06 `triangle` | 三角嘴 | 张开后是三条主要边围成的三角形开口 | 分别控制三个角与边；尖端朝上／朝下属于定向变体，闭合下撇唇线仍属于 S00 |
| S07 `quadrilateral` | 方嘴／四边形嘴 | 张开后是四条主要边围成的开口，包括方形、长方形、梯形 | 控制四角和边的圆度；长宽、上下边宽度比作为该项形状设置，不拆成多个枚举 |
| S08 `cross` | 叉号嘴／× 嘴 | 两条交叉的嘴线构成闭合符号，没有真实口腔开口 | 首版按闭合符号处理，不支持张口、露牙或吐舌；可局部拆片或用独立符号层，不允许把普通网格强拉到翻折 |

本目录中的“夸张符号嘴”明确指 **S03–S08：猫嘴、波浪嘴、折线嘴、三角嘴、方嘴、叉号嘴，共六项**。圆口与嘟嘴在 S01、S02 单列，不与符号嘴重复计数。

小点嘴／短横嘴优先由普通嘴或圆口的大小、宽度和开合得到；无需各起一个类型。只有中间一处凹凸且左右成瓣的是猫嘴；重复波动且曲线圆滑的是波浪嘴；尖锐折线是锯齿嘴，三者按目标轮廓区分。爱心、星形、螺旋图案不纳入 v1；出现明确角色需求时，补具体定义后再扩充目录。独立符号层是制作手段，不是另一种嘴型。

### 3.2 连续参数：两项基础、五项按需扩展

**收拢是宽度变化，不是与圆口、嘟嘴并列的第三种嘴型。** 普通嘴、圆口、嘟嘴都可以收拢；嘟嘴除收拢外还需要唇部曲线变化。以下范围是工作流的归一化约定，具体像素幅度与安全范围由角色绑定记录，不把所有角色强拉到同一幅度。

| 编号／固定键 | 含义 | 范围及制作边界 |
| --- | --- | --- |
| P01 `open` | 开合（基础） | 0–1，闭合到角色允许的最大开口；闭合符号形态不开放此滑杆 |
| P02 `form` | 嘴形（基础） | -1–1，下撇／自然／上扬；特殊轮廓是否支持此轴须单独验收 |
| P03 `width` | 收拢／展宽 | -1–1，0 为当前预设基准宽度，负值收拢、正值展宽；角色绑定的最窄宽度须大于零，避免网格塌缩 |
| P04 `shapeAmount` | 特色轮廓强度 | 0–1，从基础轮廓到当前选中的特色轮廓；仅对已制作连续过渡的预设开放，离散符号切换不假装支持连续形变 |
| P05 `asymmetry` | 左右嘴角偏差 | -1–1，与 P02 共同控制左右嘴角；歪嘴笑作为组合预设，不再新增嘴型编号 |
| P06 `offsetX` | 嘴部水平偏移 | -1–1，0 为原位；口周皮肤同步，外缘回接脸底 |
| P07 `offsetY` | 嘴部竖直偏移 | -1–1，0 为原位；同样需要局部皮肤联动 |

每个轮廓仅显示其已支持的参数及范围。三角尖端朝向、四边形边长比例、波峰数量作为该轮廓的制作设置；左右方向、大小与强度不各建一套轮廓编号。参数数量不能直接当作制作任务数量。

### 3.3 可叠加的附加制作项：六组

这六组描述部件或联动能力，逐子项登记支持情况；它们不占用轮廓选择，不计为六种新嘴型。

| 编号 | 制作组 | 明确子项与优先方法 |
| --- | --- | --- |
| F01 | 虎牙／尖牙 | 皮肤色唇尖、白色牙尖、闭嘴外露。皮肤色尖角局部塑唇线；白色牙尖先变形现有牙面或拆局部网格，外露部分独立挂接和裁切；左／右／双侧是配置 |
| F02 | 牙齿表现 | 上牙露出、下牙露出、咬紧。分别控制露出量和接触位置，不随嘴高把整排牙压成白线；有牙层不代表已经完成咬牙姿态 |
| F03 | 舌部表现 | 口内随动、直向吐舌、侧摆、卷舌、舔唇五个子项。分别记录能力；根部保持连接与遮挡，尖端控制伸出及弯曲，舔唇另需沿唇缘运动与接触约束 |
| F04 | 唇部／口周装饰 | 唇彩、痣、花纹。紧贴层复用对应顶点映射和关键形，不只共享平移；原画已有且受嘴动影响时，其随动为该角色必做 |
| F05 | 口中物品 | 对角色实际拥有的物品逐件绑定，记录含住位置、随动及遮挡；保持物品自身形体，不压成唇线 |
| F06 | 脸颊／下巴联动 | 大张嘴时下巴运动、鼓腮、嘴角牵拉脸颊三个子项。按需求增加局部控制，与头部父级组合，不把嘴部形变粗暴传到整张脸 |

### 3.4 组合与工作流约束

1. 工作流先完成基础七项，再选角色需要的 S01–S08、P03–P07、F01–F06。原画身份特征自动转为该角色必保留项，不能被“选做”标签排除。
2. 每次预览选择一个目标轮廓；可组合附加能力。例如“猫嘴＋虎牙＋吐舌”记录为 S03＋F01＋F03 的组合并单独验收，不再生成一个新嘴型编号。不能因三个单项可用就假定组合可用。
3. 每个轮廓需记录闭合姿态、可用开合区间、可用参数和允许附加项。S08 固定为闭合符号；S04／S05 仅做了闭嘴版本时必须标明仅闭合，不能默认推出可张口版本。
4. 从普通嘴到特色嘴需声明连续形变、经闭合姿态切换或离散切换中的一种方式。相同拓扑的关键形经过检查后插值；涉及交叉线或独立符号层时不直接跨拓扑插值，也不默认用淡入淡出导致双嘴线。
5. 禁用组合应在制作预览中解释原因；不静默把张嘴、牙齿或舌头参数套到不兼容的符号上。每项制作结果记录复用原层、调整网格、局部拆片或具体补画的依据。

## 四、逐角色能力清单

每项记录目录编号、需求来源、对应图层、参数范围、关键形、过渡方式、可组合项、检查结果和必要时的具体素材缺口。F 组的子项分别记状态，不能以一个“舌头已完成”代表五种舌部能力。状态区分为：

- **已验收**：目标范围和相关组合确实检查过。
- **待制作**：有需求，准备复用现有素材实现，尚未验证。
- **缺素材**：已发现具体缺失表面或不可接受的纹理拉伸，注明局部补画内容。
- **不启用**：角色无此表现需求；若后续需求变化可以重新评估。

新增特性时先检查与基础开合、嘴形的交叉组合。无需把所有特色参数做成完整多维排列；仅对实际组合与容易出问题的边界增加修正。对用户已有手调值保留覆盖，不因自动扫描或换页回到通用默认值。

## 五、如何判断一个可选项适合角色

按以下顺序逐项记录理由，不能只根据“有这个图层”或“技术能做”自动选中。

| 判断 | 要回答的问题 | 结果 |
| --- | --- | --- |
| 原图身份 | 原画是否本就有这种嘴线、虎牙、装饰或口中物品？像素语义是否正确？ | 已有身份升为必保留；语义不清先纠正分层，不能照图层名字绑定 |
| 表演需要 | 用户要求或角色性格是否有具体场景：调侃、疑惑、不满、惊讶？ | 写明用途；无用途不扩项 |
| 画风相容 | 唇线厚度、曲率、口内画法能否承受该轮廓？ | 可降低幅度或选择更贴合的替代；“成熟角色”并不等于只能微表情 |
| 素材与拓扑 | 现有图层是否包含实际要显露的表面？变形会不会拉糊、翻折或牵扯邻接部分？ | 优先原层形变，其次局部拆片，只有明确缺失才补画 |
| 运动与组合 | 闭合、微张、中间过渡、与其他已选项组合是否自然？ | 记录安全范围、关键形、切换策略与禁用组合；不能只看终点 |

例如：普通嘴的局部曲线能形成 ω，S03 不预设要重画；原画没有虎牙且用户不要求新增，F01 不启用；已有舌层只能证明存在口内舌头素材，不能证明卷舌、侧摆或舔唇可用。

每个能力记录至少包括：

```text
角色 / 原画版本 / 编号及子项
需求来源与身份依据
语义图层及原画坐标
选定范围与参数范围
关键形、过渡方式、允许和禁止组合
制作方式：原层形变 / 局部拆片 / 具体补画
检查范围与结果：功能检查 / 视觉检查 / 用户反馈
状态：已验收 / 待制作 / 缺素材 / 不启用
```

“首批已选”“后续候选”描述优先级，不替代以上制作状态。一个 F03 不能用一句“已完成”包办五种舌部能力；基础口内随动已经计入必做，也不重复计为新的吐舌选项。

## 六、工作流数量口径

- 基础工作七项；基础轮廓 S00；基础参数 P01、P02。
- 可选轮廓八项 S01–S08，其中夸张符号嘴为 S03–S08 六项。
- 可选连续参数五项 P03–P07；收拢属于 P03，不是新的轮廓。
- 附加能力六组 F01–F06，逐子项判断，不能把六组当成六个等量制作任务。
- 组合不新增编号；经闭合切换、连续形变和离散符号切换分别登记。

Jianma 的首批集合是 **S01、S02、S03、F03（仅短直吐舌）、P03、P04、P05**；不加虎牙。案例及仍未通过的牙唇问题见[实战记录](cases/jianma.md)。目录键 P04 为 `shapeAmount`，当前示例代码字段是 `amount`；这是字段映射，不是另一个参数。
