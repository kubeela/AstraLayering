# Web 交互原型

从仓库根目录运行：

```bash
pnpm web
# 可选：pnpm web --port 4388
```

默认打开 <http://127.0.0.1:4387>。Web 入口位于 skill 外，没有新增前端依赖。

支持通过反向代理挂载到子路径：页面、图片与 API 均使用相对地址，代理去除路径前缀后转发到 4387 即可。`GET /healthz` 提供服务状态。GameClaw 的「人物形象拆分工作台」通过站内地址嵌入此服务，不要求浏览者访问服务器的 localhost。

这轮用于确认交互与视觉设计：任务进度是明确标注的示例，新建／运行按钮不会启动 agent，目录选择仅在浏览器中保存。正式的任务启动、服务器持久追踪、状态读取以及默认运行路径调整尚未接入；没有移动或修改现有运行数据。

已连接真实内容：

- 制作页面是一张可平移、缩放的完整流程图，五条管线沿横向排列，内部步骤沿纵向连接。重要中间步骤默认全部展示，缩放只改变大小；没有 A/B 布局、独立明细页或只显示大阶段的替代视图。
- 准备阶段直接展示简化角色、素体和纯衣服参考。各 raster 步骤挂载各自的 KRA、PNG 和报告；衣服 step01 另有灰底输入、RGB 控制图、生成候选与跨深度拆层对照。局部修画对照挂在 step02 内。
- 人物 preparation 保留新增的标准参考步骤：未开启 `--standard` 时保存原图为 `standard.png`，开启时先判断再按需调整。当前 jianma 旧示例没有这张图，显示缺失说明；文件清单包含 `part-layering/references/standard.png` 时直接展示图片，不把旧示例的缺失写成固定状态。
- part 的逐层拆分在图中展示轮廓、复核、同层去重、补全、检查和直属拆分六个环节。实际 `groups.json` 树也在图中，支持树深度筛选和搜索；选择 group / part 后，六个环节切换到它对应的 SVG 与 JSON 记录。终止 part 不再拆分，整层完成后进入下一层。
- 点击图中的图片或记录，打开一个浮动查看面板，用于放大、参考对照或阅读原文；关闭后保持画布位置。中间步骤及产物仍在同一张图上。缺少的归档不以最终结果代替，标准化姿态图未收录的情况明确标注。
- raster 展示 step01、step02，以及 step02 内的绘制、两轮 review / 修复；人物另有 step03，组装只有一个 step01。review 通过可以提前结束；第二轮修复后不再 review。这里只增加进度预览，启动／恢复仍以整条管线为单位。
- 所选 Git 版本的提示词 Markdown、工具 description 与 schema；支持本地工作区、已有分支／远端引用和提交历史，并可比较版本差异。读取历史版本时兼容 skill 目录与旧 `workflow-next` 目录。只读，不执行 checkout、fetch 或修改配置。

`web/progress.js` 的步骤定义对照现有调度器组织，不参与调度。jianma 归档没有保留逐步执行记录，所以这些子步骤的状态也明确标为示例，不从产物数量推断进度。后续接入真实任务时，按现有 part 的阶段记录、raster 的 `.running` / `.completed` 及 review / repair 报告读取状态；不另造恢复机制。

服务启动时读取 `demos/jianma` 的归档文件清单；页面只为实际存在的文件提供预览。图中参考图、阶段图片及报告的映射在 `web/progress.js` 中，与示例执行状态分开维护。没有修改绘制提示词、调度器或运行数据。

确认过的正式版范围：五条管线分别运行；新任务只需一张输入图；一个持久保存的运行根目录，自动追踪其中各任务；仓库默认 `<仓库>/.run`，独立安装的 skill 默认 `<skill 上一级>/.run`；运行数据受 Git 忽略。
