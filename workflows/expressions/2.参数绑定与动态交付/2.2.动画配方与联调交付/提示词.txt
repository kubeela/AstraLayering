一、动画是实际数值轨道
每个动画写 label、description、duration_s、loop、seam、fade_in_s、fade_out_s、exit、tracks；track 写 parameter、blend、interpolation 和按时间递增的 time_s/value 键，起点 0、末点等于时长，不用文字代替运动。
- 高光/星星/爱心需要的闪动或缩放是轻量循环，幅度符合原画，不把眼内光点放大到压住睫毛；普通 control 轨道按权重混合。
- 下落泪/流汗分显现强度与运动相位，phase 是 animation 访问的 0—1 数值，由 replace 全程驱动，phase 绑定 opacity 时运行时再乘动画有效权重，不能用半权重只走半条下落路径。
- 泪滴出生 attachment 使用 cycle_start 和本次真实循环 clock，保存在脸部父空间，每周期采样一次眼缘；积泪连续跟随。不同滴需要独立运动时使用实际独立素材及参数/时钟，不能让多个同名时钟争同一个出生包装层。
- 面条泪在实际蒙版内流动，汗珠在柔化区域出现和消失；hidden_reset 在视觉不可见时回起点，不能只把 seam 写成 hidden_reset 就算无缝。
- 怒标、问号/叹号按规格跳动/摇摆或单次弹出，单次轨道末段写渐隐，结束后移除贡献；环绕爱心有真实前后分层和交接隐藏段，运行时不支持动态 z-order，不能伪造一个此类字段。
continuous 循环轨道首尾一致；fade/finish_cycle 按能力安排，流泪撤销时可让在途泪滴走完再消失。自动眨眼优先使用乘法包络与固定闭眼配合，不另开一个争用眼开度的 replace；同一参数同时多个 replace 应在设计中避免，必要冲突通过明确的调用安排提示。

二、用户枚举与程序参数分开组织
按 specification.recipes 逐项写 expressions：label、description、稀疏 parameters 配方、引用动画及 speed/weight、fade_in_s/fade_out_s。眼部、嘴部、脸色、泪液、符号各自有公开能力，哭泣不是一个不可拆的整脸图片切换；中性是基准配方，真正恢复默认使用 reset 清空其它贡献。
保留微笑、闭眼笑、悲伤、愤怒、惊讶、困倦/无奈、单眼眨眼、哭泣及已确认特效入口；惊讶可组合叹号、汗颜可组合汗珠/黑线、星星眼可组合笑口。生气是否出怒标等遵循已确认样式，组合不靠模型偷偷修改 SVG。
constraints 使用现有 when/require/message，描述真实不兼容或明确前提，例如吐舌需要适合开口、静态替换眼不支持某种眨眼；已承诺支持的替换眼型+泪液必须实际做完，不能通过新增禁用规则逃避制作。每条限制给用户能理解的原因，不能默默钳制或丢弃指令。
运行语义按 preview_manual：同实例重复调用不重启，表情撤销只释放自己的贡献，手动层覆盖配方；暂停/定位/速度控制使用真实实例 id，配方启动的子动画使用“表情实例/动画id”。LLM 用 command 调能力，不修改 rig 或任意执行代码。

三、一次有重点的真实联调
在 expression-preview 中加载最终位置的 SVG+JSON，先跑 validator，再实际看以下与本轮相关的项目；已有成功证据复用，出了具体问题只修对应对象，不做全参数笛卡尔积或反复全套检查：
1. 默认面容对比输入、reset 后无残留；眼开闭/笑眼中间态、视线四角、嘴开合×悲喜中间态，确认裁切、牙舌、唇彩、皮肤柔影随动。
2. 原/替换高光、星星/爱心与眨眼；泪液+普通眼及承诺的替换眼型，出生后闭眼不把已下落泪滴拉回，透明叠加和渐隐不露硬边。
3. 代表性配方及所需组合，至少覆盖哭泣、惊讶+符号，以及本轮新增最复杂特殊项；同时判断眉眼嘴神态、补全部件的画风和默认人物身份。
4. 循环至少两轮、单次进入/退出、暂停/继续、调速、重复同实例调用、退出/复位；一条故意错误或冲突的指令应被拒绝且保持上一状态。
若无法运行浏览器或实际产物不能加载，如实报告 blocked 及已完成范围，不以 schema 通过替代动态验收；运行时确有缺陷时定位并报告，不把失败硬归于角色然后乱画。

四、交付
final_svg 与 final_controls 同目录，controls.svg 使用实际相对路径，最终 SVG 保存默认状态；已有输入文件不覆盖。
commands 是目录，每个文件本身为 schema 合法的 command，至少一个 reset 指令和每个用户验收配方的“reset 后 apply_expression”指令，另保留代表性组合与必要控制示例；不能用自创总数组取代标准 command。文件名用安全 id，引用真实 character_id/参数/动画。
acceptance 为简短 Markdown，列启用能力和枚举覆盖、实际测试过的组合/循环及结果、已确认限制和修复后的真实遗留项；附少量已查看的默认/代表表情画面或短录屏路径即可，不做哈希链。preview 为代表性表情对照图，不把它当作动画验证本身。
