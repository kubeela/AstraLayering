## 执行入口

`SKILL.md` 所在的 `expressions/` 是任务资料根；工具、schema、样例及预览器统一放在仓库根 `agent-tools/`，不用读取另一个 skill。将来提升到 `.agents/skills/live2d-expressions/` 时整体移动任务资料并同步公共工具相对路径，由 DSL 检查验证，不复制另一套工具实现。

```text
expressions/                 # 安装后可命名为 live2d-expressions/
├── SKILL.md                 # 通用规则
├── 流程.yaml                # 输入定义
├── docs/                   # 随包 DSL 规则
├── 1.素材与关键形制作/
└── 2.参数绑定与动态交付/
```

`run`、`asset` 相对各自 YAML 解析，工具输入统一指向 `agent-tools/`；工具以自身位置寻找依赖，产物仍写入用户的工作目录。`loading/` 保留原网页地址并跳转到同一份公共预览器。

按 [SKILL.md](SKILL.md) 的通用调度规则执行 [根配置](流程.yaml)，使用时提供角色 SVG 和输出目录；原画参考与表情需求可直接补充，不要求用户制作 JSON。

```text
执行 workflows/expressions 的人物表情制作工作流。
角色 SVG：<角色 SVG 绝对路径>
输出目录：<本轮绝对目录>
原画参考：<可选，未提供则以 SVG 渲染为风格基准>
表情需求：<可选，已有选择或自定义表情；缺省按基础清单提出具体方案>
```

| 2.2 动画配方与联调交付 | 同一绑定 worker 完成动画、周期出生附着、表情配方、约束与代表性真实联调；直接交最终文件 |

语言节点均为 `gpt-6-sol-xhigh`，生图使用 `imagegen.model`；共同修改 SVG 的四个制作节点串行续用 `expression_drawing`，未启用的职责通过分支直接复用前序 SVG/材料，不派空任务。绑定的两个节点续用 `expression_binding`，没有额外全套再组装或最终独立 review。

**画风是实际制作和审查要求**：所有新增内容依据原画的线质、色温、材质、边缘与夸张程度；生图用于角色专属风格参考，默认面容以输入为准。各 worker 的提示词已分别融入相关教程方法，运行时不绑定教程全文；所需工具及离线预览器统一由 agent-tools 提供。

制作阶段的 `materials.json` 登记参数、真实实体与归属，复用 schema 的 parameter/path_morph/anchor 定义；眉眼嘴审查前允许尚无形变绑定，不填不完整网格。`关键姿态/<owner_node>/<pose_id>/` 内的 `character.svg` 是精修静态目标，`command.json` 用既有 command 的 reset + set_parameters 声明对应控制值，数值与枚举都可表达；绑定阶段必须复现它，不另造运行协议。后续素材不会被早期整张目标 SVG 覆盖，绑定只按主责 id 提取局部变化。

完整运行格式仍只有 schema 的 rig 与 command，内部 components 不进入最终 controls；最终文件为 `final/character.svg`、`final/controls.json`、`final/commands/*.json`、`final/表情对照.png` 与 `final/验收.md`，输入文件保持只读。

## 2. 两阶段 SOP

输入仍然是：**分层角色 SVG、输出路径，以及可选的表情需求**；上述清单作为默认制作范围，特殊款式有参考时再补图，不要求用户准备中间 JSON，也不从“人物动作”扩展出身体动作的确认关卡。

### 第一步：补齐表情素材与形变关键形

先核对实际 SVG，确认基础清单的样式、保留动作和排除项，随后按眼部、嘴部、脸部及外部符号分少量完整批次制作；全部语言 worker 使用 `gpt-6-sol-xhigh`。

- **眉眼**：眉形、普通/笑眼开闭、视线等关键形；补齐高光/眼黑变体、星星爱心和替换眼型，开口蒙版、眼周层次同步准备。
- **嘴部**：开合×嘴型关键形、牙舌遮挡与唇周材质；特殊嘴型及吐舌按确认的动作范围补齐。
- **泪液与脸部**：积泪、泪滴、面条泪、脸红、脸黑、黑线、汗珠，以及必要的蒙版和运动起止形。
- **符号与外部贴图**：怒标、`!`、`?`、环绕爱心、对话框等；固定点、前后关系和运动留白都在本步准备。

第一步交付默认状态完整 SVG、精修静态目标和对应标准 command，以及材料/锚点说明；眉眼嘴先完成造型审查，拓扑相容和全网格由第二步保形整理。新贴图默认隐藏，已有素材优先复用；静态目标是制作依据，运行时仍用可组合的局部控制，不整张切换脸。

此时应明确“什么要动、跟谁动、补哪些形”，不要求第一步手写控制程序；第二步若发现关键形缺口，只回补对应部件。

### 第二步：生成标准控制 JSON 并接入共用运行时

以第一步实际产物为依据，生成 `controls.json`：实际 SVG 节点→控制参数→形变/材质映射→动画轨道→表情配方；每个引用必须能定位，不能写“实现自然眨眼”之类的描述代替数值关键形。

同一负责人将 JSON 接入共用预览，检查代表性组合并交付；共用运行时只开发一次，后续角色只提供 SVG 与控制数据。SOP 保持两阶段，内部任务数量根据真实复杂度调整，不将“写 JSON、重新拼装、再截图、再核对”拆成重复工序。

第二步的完成条件：用户能通过预设看效果，程序能独立控制参数和动画，返回默认后不残留贴图或变形；schema 通过只是其中的文件检查。

## 3. 标准 JSON 的职责

[expression.schema.json](../../agent-tools/expressions/expression.schema.json) 使用 [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12)，是本项目的 SVG 控制协议草案，不是 Cubism 的直接导入格式；同一 schema 接受两种文档。

### `document_type: rig`：第二步生成的完整控制定义

| 字段 | 内容 |
| --- | --- |
| `schema_version / character_id / svg` | 协议版本、角色身份、相对 `controls.json` 的 SVG 路径 |
| `parameters` | 连续或离散参数，语义、范围、默认值与 `public/animation` 可见性；数值参数另标明 `control/phase`，公开参数供 LLM 调用，内部相位由运行时驱动 |
| `anchors / attachments` | 实际节点上的局部点或路径顶点，附着关系、偏移和采样时机 |
| `bindings` | 参数到路径形变、透明度、局部变换或贴图变体显隐的确定映射 |
| `animations` | 时长、循环、关键帧轨道、插值、进出和循环接缝；只驱动已声明的数值参数 |
| `expressions` | 用户枚举入口的标签、参数配方、关联动画与淡入淡出；兼容项可组合 |
| `constraints` | 条件与必须满足的参数关系，用于拒绝尚不支持的组合并给出原因 |

`bindings` 支持：

1. `path_morph`：一维关键形插值、二维规则网格双线性插值，例如嘴开合×悲喜嘴型；保存实际路径数据，关键点数量和命令顺序一致，含原始默认形。
2. `scalar_map`：数值映射到透明度、X/Y 位移、缩放或旋转；明确旋转/缩放中心，只操作第一步安排的局部控制层。
3. `variant`：离散选择对应已有 SVG 组的显隐，眼黑、高光、完整眼型使用各自参数；同一组只归一个显隐写入者。

v0.1 路径约定为显式绝对 `M/L/C/Q/Z`，第二步在保留已审造型的前提下统一拓扑和命令；大面积皮肤/复杂网格的变形若现有路径方式不能保持材料连续，应报告具体协议缺口，不把不支持的效果藏进自然语言字段或任意脚本。

### `document_type: command`：LLM 的运行指令

LLM 接收角色当前公开参数、可用表情、动画及限制的精简目录，只发送已声明能力的调用；不需要每轮重发素材、路径或整个控制定义。

```json
{
  "schema_version": "0.1.0",
  "document_type": "command",
  "character_id": "contract_demo",
  "actions": [
    {
      "op": "apply_expression",
      "expression": "surprised",
      "instance_id": "reaction",
      "weight": 0.8
    }
  ]
}
```

样例中的 `surprised` 引用张口参数和 `exclamation_pop` 动画，因此这条指令表达“惊讶并出现叹号”；调用者也能单独启动叹号，或只设置眉眼嘴参数。

指令包括：设置参数、应用/撤销表情、播放/停止/暂停/继续/定位动画、修改动画速度、重置；没有任意代码执行字段。未声明的参数、素材或表情需要先补制作，不能由一次控制指令凭空产生。

## 4. 运行时必须遵守的含义

以下约定已接入共用 SVG 预览运行时，使用方法与实现边界见 [控制台说明](../../agent-tools/preview/expression-preview.md)；人物素材的实际视觉效果仍需逐角色验收。

- **单位与坐标**：时间为秒，旋转为度，位移/锚点用 SVG 局部坐标单位；左右使用角色自身左右。缩放与旋转以 `pivot` 为中心，局部变换按平移×旋转×缩放合成，不依赖 JSON 字段排列顺序；控制变换使用独立初始单位变换的 wrapper，保留原有图形变换。
- **取值与插值**：路径按参数区间插值，二维关键形必须覆盖完整网格；标量曲线按 `linear/smoothstep/step` 求值，`step` 保持左键值至下一键。默认参数求得的几何必须与源 SVG 一致，裁切路径也通过同一机制控制。
- **跟随**：先求形变，再从变形后节点计算锚点，将其变换换算到附着层父坐标系中，避免重复跟随；`position` 只取锚点位置，`affine` 同时继承源节点的仿射方向/比例，均不声称自动继承任意非线性皮肤形变。
- **泪滴出生**：积泪连续跟随眼缘；下落泪使用 `cycle_start` 在每周期开始采样眼缘位置并存于脸部局部空间，脸继续运动时会跟随，但闭眼不会把已下落的泪重新拉回眼缘。需要更复杂多滴效果时使用复用素材的多实例和错开周期，不能把所有泪都绑在同一实时眼缘点上。
- **参数合成**：从默认值开始，多表情对数值通道按权重混合：总权重不足 1 的部分保留默认值，超过 1 则归一化；离散通道只能选择一致的非默认值，冲突则拒绝。直接参数设置作为持续手动层覆盖表情结果，随后合成动画，最后检查范围/约束。
- **动画轨道**：同一通道先加 `add` 的增量，再乘 `multiply` 的因子，最后使用 `replace`；轨道权重分别缩放增量、把因子向 1 混合、把替代值与当前值插值。同一通道同时存在多个 `replace` 动画必须拒绝或先停止旧实例，不采用最后写入者碰运气；自动眨眼可用乘法包络，固定闭眼用基础值 0。
- **相位与幅度**：`role: phase` 限定为内部 0～1 相位，由 `replace` 轨道以全值驱动，权重不能缩短下落轨迹；其标量透明度绑定结果再乘该动画的有效权重，位置/形状仍按完整相位求值。星星缩放属于普通 `control`，按轨道权重向默认尺寸混合；样式、速度与必要幅度分别控制，没有幅度意义的项不额外开放。
- **启动与结束**：同一 `instance_id` 再次应用同一能力只更新权重/速度，不重启相位；改变能力前先释放原实例。循环时相位连续，`continuous` 接缝数值相同，`hidden_reset` 只能在实际不可见处回到起点。单次动画结束后撤销其贡献，不永久停在终帧。
- **退出与控制权**：`fade` 按指定时间撤销，`finish_cycle` 停止新周期、让当前周期完成；结束前保留本实例所需的显现控制，再统一淡出。撤销表情只撤销它启动的动画与参数贡献，其他实例的同名能力继续生效；由表情自动启动的动画实例使用 `表情实例/动画id` 的确定名称。
- **暂停与定位**：暂停冻结当前时间，继续从原位置前进，速度改变不得跳相位；定位按本次播放已保存的出生锚点计算，不声称能重现未记录的历史头部轨迹。重置清空实例及手动层，恢复 SVG 的原始默认值。
- **错误处理**：指令批次先完整校验，再原子应用；未知能力、错误范围、冲突替换及不满足的 `constraints` 返回原因，不悄悄丢字段或改成另一种表情。运行状态检查包含动画实例是否存在、定位时间是否合法，以及合成值是否合法；样例验证器不替代这些运行检查。

## 5. 验收与当前验证范围

第二步在同一预览中核对：默认与复位、关键形中间态、眼内效果＋视线＋眨眼、泪液＋普通/所需替换眼型、嘴型＋已承诺说话/吐舌，以及叹号等符号的进入—运动—退出；循环至少看两轮连接处，再验证暂停、调速和撤销后无残留。

schema 检查字段结构；[validate_contract.py](../../agent-tools/expressions/validate_contract.py) 另外检查真实 SVG id、参数与动画引用、范围、形变拓扑和二维网格、默认几何、时间顺序及附着循环等。隐藏重置是否确实不可见、混合后的实际外观、材质跟随、运行实例冲突等仍须运行时与视觉验证。
