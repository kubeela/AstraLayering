# 四管线共享重构差异审计

基线：重构前 `76330f54`。范围：四条管线的全部 70 个实现 TS 文件、提示词及参考目录、工具定义、测试改动、安装配置，以及已迁移的运行数据。此前的重构提交为 `fe3043ff`，第一轮提示词修正为 `fe2279fe`；本记录包含随后扩大到调度流程的复核。

本次核对同时比较旧人物、旧衣服两份实现与共享实现，不将任意一边直接视为另一边的标准。原先两个 part 实现有 7 个文件存在差异，两个 raster 实现有 4 个文件存在差异，这些差异分别追踪到各自配置或保留的本地代码。

## 之前为什么漏掉

首次抽取同时做了目录迁移、工具定义搬出、差异配置化和措辞调整，审查没有建立逐项差异清单。检查重点落在 Markdown 正文、正常路径与现有测试，漏看了图片说明、运行时追加文字及部分输入边界。新旧测试都能通过的正常场景，不能证明未覆盖的边界仍然一致。

这使“共享实现”被错误扩大成了“统一某些原本不同的规则”，也让少量手工转写发生了删减。以下偏差均不属于用户授权的重构目标，已恢复原约束或修正。

### 调度与恢复的不变量

- part 每层所有轮廓绘制和 review 完成后，先整层去重，再补全、自检、分析子组；整层结束才开始下一层。
- 默认 agent 并发仍为每次 part 运行 3 个；组任务不另设数量上限，组内步骤按原顺序执行。退避等待不占用执行位置。
- **没有默认强制限深。** 仅显式 `--max-depth N` 暂停本次制作；不传时继续至终止 part。没有新增 4 层、6 层等硬上限。
- 指定分支重做仍遵守前层与祖先完成条件；仅实际变化工件及真实引用者失效。
- raster 人物三步、衣服两步；绘制和返修复用原 thread，每次新的 review 使用新上下文。
- 最多两次 review，第二次反馈修复完成后不再进行第三次 review。原有“同一份反馈仍未修完则继续原 thread”的行为未被重构新增或删除。
- step02 的绘制、review 和修复全部完成后才写 `.completed`。`.running` 中断恢复，删除完成标记才重置该步及其后续目录并清除绘制 thread。
- 删除 review/repair 报告仍从缺失环节接续，保留该步绘画及原 thread；后续步骤失效。重置操作只作用于本管线。

## 进一步审计

在 `a7cfc1d0` 后继续检查目录迁移的实际使用入口、异常参数、工具配置注册及标记组合，发现两类额外迁移遗漏：

- `acceptance-finger-priors.md` 中 11 个提示词链接仍按旧目录层级解析。修复目标路径，并补充当前布局的等价启动命令，保留原验收结论、当时实际执行的命令及提示词正文；已检查迁移示例 Markdown / HTML 中全部 698 个本地链接及预览中 346 个产物路径，均能解析到现有文件。
- 两套 preparation 测试及人物 CLI 测试只清理了管线目录，留下新的上层任务目录。改为清理该测试创建的唯一任务目录；删除了本地 56 个已确认为空的 UUID 测试目录，重跑后没有新增遗留目录。

同时复现了四处**重构前就存在**的校验漏洞，并在两套旧代码中逐项确认：先用 `String()` 判断枚举，再保留原值，导致单元素数组绕过字符串约束。

| 输入 | 实际后果 | 修正 |
| --- | --- | --- |
| 分组进度的 `status: ["running"]` 等 | 非字符串状态进入运行状态对象，不能正确归一化为待续跑 | 先检查字符串类型，再校验枚举；合法 running 仍变为 pending |
| SVG 预览的 `mode: ["blend"]` 等 | 通过参数检查后进入错误的绘制分支，还会保存错误类型的观察记录 | 在产生图片和观察记录之前拒绝非字符串 mode |
| part reviewer 的 `verdict: ["pass"]` 等 | 无效类型被写入 review JSON，后续无法当作有效结论使用 | 写报告前拒绝非法类型；允许 agent 修正参数后正常提交 |
| raster 返回的 `status: ["completed"]` 等 | 返回结果通过类型校验，但后续无法按完成/受阻字符串判断 | 明确拒绝非字符串状态；格式错误不进入临时服务重试 |

四个用例均先复现失败，修复后通过，见 [输入校验回归](../shared/tests/input-validation.test.ts)。只收紧本来不符合 schema 的参数，没有修改模型、任务要求、工具 schema、review 次数或合法输入的调度。

新增验证还覆盖：

- 本地 description 与 schema 实际注册到模拟 App Server，连续两轮保持一个 thread；定义固定在本次进程，工具回调随当前回合更新。见 [工具配置测试](../shared/tests/tool-config.test.ts)。
- 人物三步与衣服两步穷举共 150 种目录标记组合（不存在、无标记、running、completed、两标记同时存在），对比新旧 `inspectRun` / `resetSteps` 的计划、剩余文件及 thread 清除结果；全部一致，同任务其他管线的文件保留。
- 两套 raster 共 288 种 review / repair 报告组合，对比下一环节或报错；全部与重构前一致。没有额外 review、跳过返修或完成标记规则变化。

本机缺少人物 hair 原本使用的三张本地参考板副本，历史依据与本轮查找范围见下节。此前写成“尚未准备”不够准确：原流程已经配置并记录使用，不能把本机缺少副本解释成原流程没有这些参考。

上述修复后，对同类校验、标记组合、工具注册、路径隔离、示例链接及最终差异再检查，未发现新的具体遗漏。此结论覆盖可复现的代码和文件行为，不等于证明所有真实模型或服务响应都没有问题。
