# 人物分层工作流

执行入口以各级 `流程.yaml` 为准。每次选择、派发或续做节点前，先读取该节点的 `流程.yaml` 和选中的分支，再绑定资源、worker 与产物。语法见 [Workflow DSL](docs/workflow-dsl.md)。

启动制作任务前，读取[根配置](流程.yaml)，确认用户已提供必要输入和本轮绝对工作根目录；缺少其中任一项时询问。工作根目录单独绑定，不属于 `inputs`。输入素材和技能资料只读，产物与临时文件写入工作根目录。用户只要求规划或修改流程时，不启动制作任务。

`SKILL.md` 所在目录是资源根；`run`、`asset`、`prompt` 从这里解析，路径留在本目录内。通用工具放在 `tools/`，步骤工具放在该步骤的 `tools/`。

按编号执行节点，并以 YAML 声明的输入、条件、输出和审查交接。语言任务按选中分支 `worker`、节点 `worker`、节点 `id` 的顺序确定会话身份；同身份续用已记录的 worker_id，新身份才创建 worker。独立审查使用自己的 worker 身份。生图由总控按 YAML 调用。

`dispatch` 由总控按当前 YAML 推进。每次只选择一个待办节点，完成当前路由后再选择下一项。结构增长后重新读取待办，完成状态写入独立文件，成功产物按 `carry` 传递。具体树文件、字段、工具、路由和派发类型由当前节点 YAML 声明。

工作根目录的 `运行记录.md` 保存绑定、分支、worker_id、当前指针、产物与审查结论。续跑时核对实际文件和状态，再从最新成功产物继续。最终报告完成范围和未解决项。
