# Layering 调度流程约定

2026-10-09 起确认，2026-10-13 更新。本文记录实现依据。当前参考准备、首次分组、组轮廓绘制和独立 review 已接入真实 agent；以下组处理的顺序调度、进度保存、续跑和子组循环已搭建，补形、子组分析及 SVG 合并使用占位接口。

## 输入与首次分组

- 启动时先读取当前运行（同一 `--name`）已保存的分组结果与进度，再决定是否需要首次分组。`null` 不代表重置或强制重做。
- `groups === null`：实际已有组时，直接恢复该结果并进入统一的跳过／续跑逻辑。实际组为空时，才执行首次分组拆分识别。产出必须是**组**，保存结果后将这些组作为输入和待办项进入组循环。是否已首次分组只根据实际组是否非空判断，不单独记录 `initial` 状态。
- 显式传入组：选择本次运行已有分组树中的组及其子组，只处理这些分支；说明、关系和进度以本次保存结果为准，跳过已完成步骤。不登记新组，不导入外部完成进度。空选择、未知组或错误父子关系直接拒绝。
- 显式选择前，前置参考必须已存在，所选组的全部祖先必须完成一轮五个步骤，所选分支及祖先已登记的 SVG 必须实际存在。缺少结果时在启动 agent 前报错，不自动补跑前置。依赖只沿祖先链判断：`face` 未完成时不能执行 `face/eye`；`face` 已完成时可以执行，与 `hair` 是否完成无关。

两种输入共用同一套续跑判断：已有组就跳过首次分组，各组的步骤完成就跳过对应步骤，全部工作完成就不再调度 layering agent。不只看本次输入是否为 `null`。

首次分组与每组处理结束后的内部拆分是两个阶段：前者提供第一批组，后者逐步形成更细的组树。

人体头部在第一层直接分为 `face`（脸部、五官、耳朵）、`hair`（全部头发和发髻）、`head_accessories`（发冠、发夹、额饰、耳饰及头饰长飘带）。`face` 只以脸型与耳朵作为绘制、补全范围，不补头顶与后脑；长飘带始终归头部装饰物，装饰组内部留待后续细分。`neck`、`body`、`arms`、`pelvis`、`legs` 沿用原有划分。

首次分组 agent 在 `.run/<运行名>` 内工作，程序明确传入素体参考图绝对路径，不预先附图，也不让 agent 自行寻找目标图。用内置 `view_image` 看整体，细节按需用注册的 `view_bitmap({ path, crop?, scale? })` 裁剪放大，观察图保存在 `observations/initial-groups/`。同时注册 `write_groups({ subject, groups })`，工具校验一层组、名称和重复项后，直接保存本次运行的正式分组，已有组时拒绝覆盖。分组与调度器共享写入队列，进度由程序维护；不解析 agent 的最终回复，也不再生成临时分组 JSON。具体组处理 agent 继续逐项接入。

是否直接附图按各步骤的查看需求确定；需要反复查看、裁剪或渲染的文件提供明确路径，由工具按需回传图像。输入文件由程序指定。

## 每个组的一轮处理

1. **画组轮廓 + 分块自检**：依据当前组和参考图绘制组轮廓，先用整图 blend 核对位置、比例、主要形状及归属，再裁剪放大，用 blend 和 edge 逐块检查全部可见区域的边缘、接缝、孔洞、开口和尖端。发现问题在本次绘制内修正，复查改动处及相邻区域，保留已正确的形状。首层没有父轮廓时直接依据参考图；子组同时以父组完成 SVG 为范围边界。
2. **严格 review**：先整图定位，再分区域裁剪放大，用 blend 和 edge 逐块检查；范围广或分布分散的组须覆盖所有可见区域，相邻选框适当重叠检查接缝与连续性，不能只看整图缩览或少数局部就下结论。逐处核对可见边缘的位置、宽度、弧度和走向，保留明显折线、折角和转折，不能磨成弧线，也不能超出或缩入原图。重点检查轮廓是否干净、形体归属是否清晰，清理来源不明的碎发丝、孤立像素点和碎片堆砌。微小信息缺口须按参考和结构关系补成连续的局部形体，不能只画孤点表示部位存在；可靠的可见边缘、结构明确的独立饰件和分离区域须保留。
3. **直接遮挡补形**：查看补形提示词与对应参考图，补全组轮廓中被直接遮挡的部分。不扩展到侧面、背面等不可见结构的补全。
4. **补形自检**：确认补形前原有形状没有被改变，新增部分的结构合理。
5. **分析组内轮廓并生成子组待办**：基于本组完成后的轮廓，识别内部可拆分的组，将子组写入分组树并加入待办队列，等待同一循环调度。不再产生子组时，该分支结束。

严格 review 负责边缘贴合、去噪和微小缺口的局部形体完整性；大片直接遮挡仍由步骤 3 补形，步骤 4 自检保留原形和新增结构的合理性，两者职责分别记录。

步骤 1、2 的绘制会话由调度器保留，同组首次绘制和返修沿用一个 thread；每次 review 创建独立的新会话，候选只读，审完关闭。每组最多两次正式 review：绘制并自检 → review 1 → 返修并自检 → review 2 → 返修并自检 → 进入下一步。任何一轮 pass 即提前进入下一步；第二轮 revise 也必须交回原绘制会话落实意见，完成自检后直接继续，不再复审、不挂起等待通过。原始 verdict 保留，review 步骤 completed 表示本阶段流程结束，output.reviewOutcome 分别记录 pass 或 repaired，终端明确显示最后一版已返修且不再复审。轮数读取本组已保存的 review 数量，跨启动累计，服务重试不计为新一轮；返修完成的 SVG 哈希写入对应审查条目的 repairedCandidateHash，中断恢复时避免重复执行。旧记录已超过两轮时也不新增 review，先完成最后一轮尚未落实的返修。blocked 时保留该步骤待办和报告，执行异常时保存失败进度。任务结束或异常时关闭绘制会话；跨启动只恢复产物与进度。会话管理对两个 agent 的工作提示词透明。

绘制提示词 `prompts/5-组轮廓.md` 和审查提示词 `prompts/6-轮廓review.md` 复用原流程要求，适配当前组独立 SVG。`prompts/groups/<完整组ID>/outline.md`、`review.md` 分别完整替换对应正文，缺失时使用通用正文，不继承父组特化。运行输入仍由程序提供。

两步都可通过原生 `preview_svg` 查看 SVG、参考混合叠加、边缘叠加和裁剪放大，子组必须在父组完成 SVG 范围内。SVG 与参考共用画布坐标；程序校验绑定、画布、有效矢量和父范围，review 用 `submit_review` 保存结论而不是解析最终回复。各轮意见与实际观察图路径保存在 `stages/review/<组ID>.review.json`。review 直接读取轮廓 SVG，审查与返修流程结束后进度引用原轮廓路径，后续补形也读取该文件，不复制审查 SVG。

父范围检查固定使用宽、高各四倍采样，在相同网格上先比较子、父 alpha 覆盖差，再按 128 阈值识别未覆盖采样；避免共用曲线的抗锯齿差异被独立二值化放大。正常贴边及共边允许通过，父轮廓不扩张，也不按越界采样数量豁免；孔洞和分离区域继续约束子组。预览 crop/scale 不改变检查精度，越界选框和面积折算到原图单位。首层没有父 SVG 时不做此项检查。

绘制与返修开启内置 `image_generation`，review 和首次分组不开启。噪音或形体混乱导致结构难辨时，可根据原参考局部生成放大辅助图；要求结构清晰优先、不添加图中不存在的细节、不改变已有形状、比例和可靠边缘，继续对照原参考修正 SVG。同一处问题只生成一次是提示词约束。返修要求保存在 `prompts/7-轮廓返修.md`，和独立 review 反馈一起作为用户输入交给原绘制会话。

每次返修的反馈和实际完整提示词分别保存到 `stages/outline/<组ID>.repairs/<序号>/feedback.txt`、`prompt.txt`，序号从 1 递增；续跑继续编号，失败回合也保留，不覆盖此前记录。各轮完整请求继续分别记录在运行目录的 `agents/.../request.json`，审查报告保留各轮反馈。生图事件、修订提示词及工具提供的图片保存路径也保留在各轮日志中。

## 轮廓边缘优化试验（2026-10-13 已停止，未接入）

此前试验过 DexiNed 边缘拟合与 SAMRefiner 分割细化，结果不足以接入。用户现决定不引入额外模型，改为加强绘制与返修自检、最多两轮 review 并落实两轮意见。此前“边缘优化替代自检”的计划撤销，正式流程保留 SVG 格式、画布、父范围及 blend 观察校验；分块检查由提示词要求，不另设固定选框或工具调用次数。

已按用户要求清理离线试验脚本、测试、对比产物，以及专用环境和模型权重。正式流程测试、参考图、SVG 与进度保留；既有参考准备与已授权的局部辅助生图能力保持原状。

## 补形先验

补形不能只依赖通用的“补出完整结构”指令。针对需要先验指导的部位，提供专门提示词和参考图，明确补形范围及应保留的结构。

例如脸部按 Live2D 分层习惯通常只补完整脸型，不补完整头型。具体部位使用对应先验，不把这个规则套用到所有组。

后续接入 part 时，part 同样需要绘制、review 和轮廓补全及补形自检，完成后作为叶节点，不再分析或递归拆分子项。当前只接入 group，先记录这项约定。

## 产物、进度与调度

- 每个 agent 产出的 part 保存为独立 SVG，最终由程序完成 SVG 合并。
- `groups.json` 随首次分组和子组发现逐步形成完整树，只记录主体类型、组 ID、说明和父子关系。各组步骤和合并的状态及产物路径单独保存在 `progress.json`，兼容旧文件的已有进度；旧 `initial` 字段会被忽略并移除。
- 完成的独立 SVG 保存为 `parts/<组ID>.svg`，如 `parts/face.svg`；轮廓放在 `stages/outline/<组ID>.svg`，审查 JSON 放在 `stages/review/<组ID>.review.json`，review 不另存 SVG。使用可读名称，不使用哈希目录；旧进度引用的审查副本仍可沿用，不自动删除或迁移。
- 首次分组保存分组树，每个组的已完成步骤保存产物与进度；即使续跑仍传入 `null`，也依据记录跳过已完成工作，从未完成步骤继续。组内分析完成意味着本组这一轮完成，不代表其所有子组已经完成。
- 按祖先依赖调度：默认并发上限 5，通过 `--jobs` / `-j` 调整，同一组按上述顺序执行。父组完成一轮五个步骤（含子组分析与登记）后，其子组即可启动；其他分支还在运行或待接入时，不阻塞该子组。未完成父组的后代保持等待。
- agent 调用由独立的 `agent-runtime.ts` 限制，总并发默认 3，通过 `--agents` / `-a` 调整；SDK、绘制与 review 共用限制，空闲会话不占位置。临时服务失败的重试和退避也在该调用层处理，等待时释放位置；分组调度只等待任务结果，不处理重连或重新派发步骤。详见 [agent-runtime.md](agent-runtime.md)。
- 就绪组中优先派发浅层组，空出的并发位置可以由祖先已完成的子组补上，不设置全树整层等待。显式输入与 `null` 续跑使用同一套祖先依赖判断。层级来自树结构，不另存层级状态。
- 显式选择只处理所选组及其子组，不自动执行未选择的分支；所选分支的子组在祖先完成后直接进入待办。最终 SVG 合并仍需全部组完成。

## 当前结构与后续接入顺序

默认不设 agent 回合超时。单组执行异常时停止新派发，等待已启动的组结束，结果明确列出出错组、步骤和原因，并说明其余未启动待办未执行。正常退出也逐组显示 review 已通过、两轮意见修正及自检完成（不再复审）、需要返修或无法核对，以及当前等待步骤；agent 回合结束不表示 review 通过。

分组与进度类型位于 `layering-types.ts`，原子持久化位于 `groups.ts`，调度位于 `layering.ts`，入口为 `run.ts`。默认适配器集中在 `layering-steps.ts`，首次分组位于 `initial-groups.ts`，绘制与 review 位于 `outline-agent.ts`，提示词选择位于 `group-prompts.ts`，SVG 观察与父范围检查位于 `svg-tools.ts`。其余占位步骤返回待接入状态时保存进度，不生成假结果或误标完成。

后续逐个完善以下接口，分别确定 function call、自定义提示词和所需部位参考：

1. `initialGroups`：已接入首次分组识别，使用素体换装参考，保留组说明和主体类型。
2. `drawOutline`：已接入组轮廓绘制与分块自检，保存独立 SVG。
3. `reviewOutline`：已接入独立严格 review、按意见返修和审查记录。
4. `completeOcclusion`、`checkCompletion`：部位补形先验、直接遮挡补形与自检。
5. `splitChildren`：组内分析的具体 agent；子组登记、入队与循环结构已接入。
6. `mergeSvg`：程序合并接口，待独立 SVG 产物格式和组合规则确定后实现。
